# Delegation

仅在准备实际委派 Explorer 或 Solver，或处理 Research Memo、Task Memory 与子智能体上下文时读取本文。

## 1. 独立上下文原则

子智能体是局部认知工作单元。

每次委派只提供当前局部问题真正需要的上下文，使子智能体在干净可控的上下文中：

- 能独立理解任务；
- 能获得必要的上游信息；
- 不被无关的赛题历史淹没；
- 能留下自包含结果供主会话整合。

不要默认把完整聊天记录或所有赛题文件注入子智能体。

## 2. Explorer

Explorer 负责横向研究支持。

适合处理：

- System Knowledge / HMML 浏览；
- 方法候选调查；
- 领域背景研究；
- 论文和资料检索；
- 外部事实核验；
- 数据集寻找；
- 赛题附件研究；
- 多种方法的研究性比较。

研究通常优先：

```text
System Knowledge
      ↓
Case Library
      ↓
External World
```

当前层不足时再扩大范围。

主会话可以直接读取少量、明确相关的 Knowledge。需要系统性浏览 HMML、调查方法、检索资料或核验外部事实时，优先委派 Explorer。

Explorer 可以提出方法候选、证据和研究建议。全局方法选择由主会话决定；Solver 可以在其 Task 的授权范围内自主选择和调整局部方法。

### 委派 Explorer

按需提供：

- 研究问题；
- 为什么这个问题重要；
- 它支持哪个 Task 或全局决策；
- 必要的原题信息；
- 相关已有资料或认知产物；
- Research Memo 的目标位置。

不要预先规定答案。

### Research Memo

Research Memo 应足够让全新进入的智能体仅凭该文件理解：

- 研究了什么；
- 使用了哪些来源；
- 得到了哪些关键事实或方法候选；
- 哪些结论较可信；
- 哪些内容仍不确定；
- 这些结果对当前建模问题有什么意义。

这些是语义要求，不是固定 schema。

外部资料进入重要结论时，应保留可追溯来源。

## 3. Solver

Solver 负责一个有意义的局部数学建模 Task。

一个 Episode（一次求解过程）主要围绕一个 Task 工作。

### 委派 Solver

按需提供：

- Task 目标；
- 必要的原题上下文；
- 直接依赖的 Task Memory；
- 相关 Research Memo；
- 必要的 Case Library 材料；
- 当前 Task 的工作目录；
- Task Memory 目标位置。

优先传递直接依赖的 Task Memory。只有确实需要时再补充更远的历史信息。

### Solver Episode

Solver 可以在干净可控的上下文中围绕：

```text
Formulation
    ↕
Computation
    ↕
Evaluation
    ↓
Interpretation
    ↓
Task Memory
```

自治迭代。

允许修改模型、修复计算、重跑实验、比较局部方案、检查异常结果，并在 Evaluation 暴露问题时回到 Formulation。

Solver 在当前 Task 内需要方法知识、论文、数据来源或领域背景时，可以使用 Explorer 提供的研究支持，并在获得结果后继续局部求解。只要研究需求仍属于当前 Task 的边界，就不需要把它升级为全局问题。

如果缺失的信息会影响上游依赖、当前 Task 的边界或全局方法选择，或者无法在当前 Task 内可靠补齐，不要强行继续求解。按照 Task Memory 的未完成交接要求记录当前情况并交回主会话，由主会话判断是否需要补充研究、调整 Living Task Graph 或重新委派 Solver。

主会话不需要逐步介入这些内部循环。

### Task Memory

Task Memory 应足够让全新进入的智能体仅凭该文件理解：

- 当前 Task 实际解决了什么；
- 使用了什么方法；
- 重要假设与输入是什么；
- 做了什么计算或推导；
- 得到了什么结果；
- 有哪些关键文件或结果；
- 有哪些局限或未解决问题；
- 下游最需要知道什么。

没有顺利完成时，还应写清：

- 卡在哪里、已经尝试过什么；
- 为什么继续做没有意义；
- 问题是否超出当前 Task 的边界；
- 需要主会话重新考虑什么；
- 哪些已有工作仍然可复用。

用自然语言准确表达实际情况。不要依赖固定状态枚举。

## 4. 并行

相互独立的 Task 可以在宿主支持时并行。

并行用于减少等待时间。不要为了并行：

- 强制划分执行波次；
- 人为制造 Task；
- 牺牲依赖关系；
- 把 Living Task Graph 变成固定调度表。

## 5. 委派前判断

主会话根据当前建模问题的全局局势决定是否卸载，以及卸载给谁；委派用于降低局部认知负担，本身不构成目标。

子智能体是认知卸载工具。
