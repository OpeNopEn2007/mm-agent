    Role section:
    ```markdown
    <role>
    The mm-agent-coordinator agent manages the DAG (Directed Acyclic Graph) of task dependencies and coordinates the Memory system for context passing between tasks.

    Key responsibilities:
    1. Parse subproblem list from problem.md
    2. Analyze dependencies between tasks using LLM
    3. Build DAG structure and validate no circular dependencies
    4. Perform topological sort to determine execution order
    5. Load dependency task results from Memory before each task starts
    6. Write task results to Memory after completion
    7. Track task status (pending -> in_progress -> completed/failed)

    The coordinator ensures tasks execute in correct order and have access to required context from previous tasks.
    </role>
    ```

    Execution flow section:
    ```markdown
    <execution_flow>
    ## Step 1: Read problem.md for subproblem list
    Use Read tool to load .planning/memory/problem.md
    Extract the list of subproblems from the structured output.

    ## Step 2: Analyze task dependencies
    Use Agent tool to invoke LLM for dependency analysis:

    Prompt template:
    """
    Analyze the following subproblems and identify dependencies:

    Subproblems:
    1. {task_1_description}
    2. {task_2_description}
    3. {task_3_description}
    ...

    Output JSON format:
    {
      "tasks": {
        "1": { "description": "...", "dependencies": [], "status": "pending" },
        "2": { "description": "...", "dependencies": ["1"], "status": "pending" },
        ...
      }
    }

    A task depends on another if it requires the output or result of that task.
    """

    ## Step 3: Build DAG and detect circular dependencies
    Use Bash tool to execute topological sort script:
    ```bash
    python .claude/scripts/dag_topological_sort.py \
      --input .planning/memory/dag.json \
      --output .planning/memory/execution-order.txt
    ```

    If script returns error (circular dependency detected), report error and request re-decomposition.

    ## Step 4: Execute tasks in order
    For each task in execution-order.txt:
    a. Update task status to "in_progress" in dag.json
    b. Load dependency Memory files using Bash:
       ```bash
       python .claude/scripts/load_dependency_memory.py \
         --task-id {task_id} \
         --dag .planning/memory/dag.json \
         --memory-dir .planning/memory \
         --output .planning/memory/context-for-task-{task_id}.txt
       ```
    c. Read context file and pass to task agent (Modeler/Programmer/Reporter)
    d. Wait for task completion
    e. Write task result to Memory (task-{id}.json)
    f. Update task status to "completed" in dag.json

    ## Step 5: Handle failures
    If task fails (max retries exceeded):
    - Update status to "failed" in dag.json
    - Store error message in task Memory
    - Continue to next task (report failure in final summary)
    </execution_flow>
    ```

    Structured returns section:
    ```markdown
    <structured_returns>

    ```json
    {
      "task_id": "string",
      "status": "in_progress|completed|failed",
      "dependencies_satisfied": boolean,
      "execution_time_seconds": number,
      "error": "string|null"
    }
    ```

      "completed_tasks": number,

      "failed_task_ids": ["string"],

    ```

    ## Step 3: Generate initial modeling plan (Actor, round 0)
    Use Agent tool to generate initial plan:

    Prompt template:

    Generate a mathematical modeling solution for the following task:

    Task: {task_description}
    Dependency context: {dependency_memory}
    Relevant methods (from HMML):
    {retrieved_methods}

    Output in the following format:
    - Modeling method selection and justification
    - Mathematical formulas with variable definitions
    - Assumptions and constraints
    - Derivation steps

    Focus on correctness and clarity.
    """

    Store output as model_v0.

    ## Step 4: Evaluate quality (Critic, round 0)
    Use Agent tool to evaluate model_v0:

    Prompt template:
    """
    Evaluate the following mathematical modeling solution:

    Task: {task_description}
    Model: {model_v0}

    Evaluate on these dimensions (1-10 scale):
    1. Assumption validity - Are assumptions reasonable and clearly stated?
    2. Formula correctness - Are formulas mathematically sound?
    3. Method fit - Is the chosen method appropriate for the problem?
    4. Clarity - Is the solution easy to understand?

    Provide:
    - Overall score (1-10)
    - Specific issues identified
    - Improvement suggestions
    """

    Store feedback as critique_v0.

    ## Step 5: Improve modeling (Actor, round 1)
    Use Agent tool to improve model_v0 based on critique_v0:

    Prompt template:
    """
    Improve the following mathematical modeling solution based on the critique:

    Original model: {model_v0}
    Critique: {critique_v0}

    Output the improved model with the same format.
    """

    Store output as model_v1.

    ## Step 6: Repeat evaluation and improvement (rounds 2-3)
    Repeat Steps 4-5 for additional rounds:
    - If critique score >= 8, stop early (satisfaction threshold)
    - Maximum rounds: 3 (configurable)

    ## Step 7: Output final model and formulas
    Use Write tool to create:
    - .planning/memory/model-{task_id}.md (full modeling documentation)
    - .planning/memory/formulas-{task_id}.json (structured formulas)

    {
      "equations": [

          "latex": "string",
          "description": "string"
        }
      ],
      "variables": [
        {
          "symbol": "string",
          "name": "string",
          "unit": "string",
          "type": "parameter|variable"
        }
      ],
      "assumptions": [
        {
          "id": "a1",
