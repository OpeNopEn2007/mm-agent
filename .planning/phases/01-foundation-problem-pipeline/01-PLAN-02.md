# Plan 02: Verification Gates & Context Passing

**Objective:** 实现阶段验证门控和上下文传递机制，确保输出质量并支持阶段间信息流转。

## Prerequisites

- Plan 01 完成 (Core Skills Framework)
- problem.md 可被生成

## Tasks

### Task 1: Create Phase Verification Skill

<objective>
创建阶段验证 Skill，检查阶段输出是否符合规范
</objective>

<read_first>
- .planning/phases/01-foundation-problem-pipeline/01-CONTEXT.md (D-09~D-11 验证决策)
- .planning/ROADMAP.md (Phase 1 成功标准)
</read_first>

<action>
创建文件 `.claude/skills/mm-agent/verify-phase.md`，包含：

1. Frontmatter:
```yaml
name: mm-agent-verify-phase
description: Verify phase outputs meet quality standards
```

2. 内容结构：
- `<objective>`: 验证阶段输出文件存在且格式正确
- `<flags>`: --skip-verify (YOLO 模式)
- `<process>`:
  1. 检查输出文件存在性
  2. 检查必填字段完整性
  3. 检查 Markdown 格式正确性
  4. 输出验证结果

3. Phase 1 验证规则：
```yaml
phase: 01
output_file: problem.md
required_fields:
  - title
  - background
  - questions
  - constraints
  - objectives
  - keywords
  - raw_text
  - summary
format_check: markdown_syntax
```

4. 验证失败处理：
- 输出明确错误信息
- 提供修复建议
- 允许用户继续或中止

5. YOLO 模式 (`--skip-verify`):
- 跳过验证，直接进入下一阶段
- 输出警告信息
</action>

<acceptance_criteria>
- `.claude/skills/mm-agent/verify-phase.md` 文件存在
- 文件描述 Phase 1 的验证规则
- 文件包含 `--skip-verify` 选项说明
- 文件包含错误处理流程
</acceptance_criteria>

### Task 2: Create Context Passing Mechanism

<objective>
创建上下文传递机制，实现阶段间的文件传递和摘要生成
</objective>

<read_first>
- .planning/phases/01-foundation-problem-pipeline/01-CONTEXT.md (D-12~D-14 上下文传递决策)
- .planning/research/ARCHITECTURE.md (阶段化架构参考)
</read_first>

<action>
创建文件 `.claude/skills/mm-agent/context-pass.md`，包含：

1. Frontmatter:
```yaml
name: mm-agent-context-pass
description: Manage context passing between phases
```

2. 内容结构：
- `<objective>`: 实现阶段间上下文传递，支持阶段隔离
- `<mechanism>`:
  - 输入阶段: 从 `.planning/phases/XX-name/outputs/` 读取前一阶段输出
  - 输出阶段: 写入 `.planning/phases/XX-name/outputs/` 当前阶段输出
  - 摘要字段: 每个输出包含 `summary` 字段

3. 目录结构约定：
```
.planning/phases/
├── 01-foundation-problem-pipeline/
│   └── outputs/
│       └── problem.md        # Phase 1 output
├── 02-modeling-agent-system/
│   ├── inputs/               # Symlink or copy from Phase 1
│   │   └── problem.md
│   └── outputs/
│       └── plan.md           # Phase 2 output
```

4. 上下文摘要生成规则：
- 提取关键信息（如问题标题、主要目标）
- 限制长度（100-200 字符）
- 包含关键决策点

5. 传递函数模板：
```
pass_context(from_phase, to_phase, output_file):
  1. 验证源文件存在
  2. 创建目标阶段输入目录
  3. 复制/链接文件到目标目录
  4. 更新 STATE.md 记录传递
```
</action>

<acceptance_criteria>
- `.claude/skills/mm-agent/context-pass.md` 文件存在
- 文件描述输入/输出目录结构
- 文件包含摘要生成规则
- 文件定义上下文传递流程
</acceptance_criteria>

### Task 5: Create Verification Error Messages

<objective>
创建验证错误消息模板，提供明确的修复建议
</objective>

<read_first>
- .planning/phases/01-foundation-problem-pipeline/01-CONTEXT.md (VRF-02 需求)
</read_first>

<action>
在 `.claude/skills/mm-agent/verify-phase.md` 中定义错误消息模板：

1. 文件不存在错误：
```
❌ 验证失败: 输出文件不存在

期望文件: {file_path}
阶段: Phase {N}

修复建议:
1. 检查上一阶段是否成功完成
2. 确认输出目录权限正确
3. 重新运行上一阶段

命令: /mm-agent --phase {prev_phase}
```

2. 必填字段缺失错误：
```
❌ 验证失败: 必填字段缺失

文件: {file_path}
缺失字段: {field_name}

修复建议:
1. 检查问题解析输出
2. 确认输入文件包含必要信息
3. 手动添加缺失字段

跳过验证: /mm-agent --phase {phase} --skip-verify
```

3. 格式错误：
```
⚠️ 格式警告: Markdown 语法问题

文件: {file_path}
问题: {description}

建议: 使用 Markdown linter 检查
```
</action>
