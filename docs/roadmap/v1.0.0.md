# v1.0.0 Roadmap

## 目标

构建第一个可用的 OpenCode Plugin 版 MM-Agent Harness，把 Canonical Core 落地为端到端 Case，并让唯一的 `/mm-agent` 用户路径由正式 Flow 驱动五个 hidden Agents。

当前状态：正式运行面已通过外部 npm `.tgz` 独立项目验收；`1.0.0` 尚未 npm publish。Golden runner 是开发期验收工具，不是产品 runtime。

`v1.0.0` 的 Canonical Core 与 OpenCode Adapter 分别由：

- [Canonical Core](../architecture/canonical-core.md) 定义宿主无关的 Case、artifact、context manifest、review 和 gate 协议。
- [Artifact 协议](../context/artifact-protocol.md) 定义 Case 文件职责、状态推进和完成规则。
- [OpenCode Plugin Harness](../architecture/opencode-plugin-harness.md) 定义唯一活跃 Adapter 的接口；正式 Flow 收敛规格见 [formal-runtime-convergence](../architecture/formal-runtime-convergence.md)。

Pi CLI Extension 与旧 Claude/Codex Plugin 不再是活跃 runtime 决策，资产保留在 `.archived/legacy-claude-codex-plugin/`，仅供回溯。

## 已接受验收标准

- 用户通过唯一入口 `/mm-agent` 创建或恢复 Case。
- 正式 Flow 暴露 `advance` / `submit_review`；模型可见 Tool 只有 `mm_agent_check`、`mm_agent_prepare`、`mm_agent_flow`、`mm_agent_hmml`、`mm_agent_compute`、`mm_agent_compile` 六项。
- 五个 hidden Agents 为 `mm-analyst`、`mm-modeler`、`mm-solver`、`mm-writer`、`mm-critic`；四个 Skills 均按项目级发现加载。
- Plugin API 不直接调用 built-in `task`；Skill 机械发出一次 Task，`tool.execute.before` 原地校正 Agent、description、prompt，并清除 `task_id`、`background`、`command`，保证 fresh foreground child。
- `mm_agent_case` 不注册给模型；内部 `runCaseAction` / `FileCaseContextStore` 保留 `open / dispatch / gate / inspect`，Core Gate 仍是唯一 promotion/state 入口。
- `handoff.json` 由 Flow 从权威 Case 文件派生，仅作恢复投影；旧持久 `schema_version: 1` Case 可懒生成 handoff，不改写既有数据。
- Review evidence 受 Manifest candidate/read/rubric、immutable input/accepted upstream 和当前 Attempt Runtime Evidence/hash allowlist 约束；未声明路径不得通过 Gate。
- Solver task 在正式首链按 DAG 可执行顺序串行运行；Golden runner 不驱动正式用户 Case、不进入 npm package。
- `blocked` 不自动回滚已接受阶段；缺少输入或 accepted upstream 错误时，需新 Case 或未来显式 reopen/migration。
- Case 完成要求四阶段 artifacts、`main.tex`、`compile.log` 和非空 `report/report.pdf`，并由 Gate 验证。
- package 以真实 `package.json.files` 清单为准，不声明或打包不存在的 `schemas/` 目录；测试、Golden runner、Case、trace、cache、模型权重和凭据不入包。

## 外部正式运行面证据

外部 npm `.tgz` 独立项目使用 OpenCode `1.18.9` 与 `minimax/MiniMax-M3`，用户仅执行 `/mm-agent`。正式 Flow 完整运行 Analyst → Modeler → Solver DAG（按可执行顺序串行，含 revision）→ Writer → Critic，未使用 Golden runner；五个 hidden Agents、四个 Skills、六个最小公开 Tool 均成功发现，59 个 completed built-in task 的 child session ID 全唯一（analyst 1、modeler 1、solver 24、writer 2、critic 31）。

真实 uv/Python 3.12 计算留下 Compute Evidence，真实 XeLaTeX 编译留下 Compile Evidence。`main.tex` 为 34989 bytes（SHA-256 前缀 `762877…`）、`compile.log` 为 29154 bytes（SHA-256 前缀 `ad917d…`）、`report/report.pdf` 为 1720007 bytes（SHA-256 前缀 `2d6c8e…`）；最终 Case 为 `completed`、stage `reporting`、revision `27`，handoff `completed` 且 blockers 为空。PDF 为 A4 17 页，逐页渲染目检无裁切、重叠、缺字或黑块，最终 compile/review 通过，三个结果 XLSX 存在；最终 `main.tex` 无 TODO/TBD/PENDING/placeholder/TO VERIFY 命中。

独立受控中断实验：在 analysis-001 三输出落盘、revision 0 时精确终止 OpenCode；新会话从 mm-critic 接续，仅创建一个 Critic child，Analysis Attempt 仍为 1；pass 后 revision 1 / modeling，在 Modeler 执行前停止。多次进程中断均从同一磁盘 Case/Attempt 接续。`1.0.0` 仍未 npm publish，第三方 notices 再分发授权仍是公开发布边界。

上述证据证明正式 Flow 用户路径、磁盘恢复和真实计算/编译能力；开发期 Golden A/B/C 仍作为补充回归证据，不替代正式 Flow 验收。

最终回归为 `npm test` 179 total / 168 pass / 0 fail / 11 skip，build、validate-config 和定向复审均通过。

最新 `npm pack --dry-run` 候选为 122 files、packageSize 2,185,700 bytes、unpacked 3,288,455 bytes、SHA-1 `042e284b2d7d6ac6b7b8f1eac4cf546bbc8a00d8`；仅作为最终包清单/大小证据，不声称长模型链在该候选上重跑。

## 发布边界

- `1.0.0` 仍未 npm publish；公开发布前需解决第三方 notices 中未明确授权资产的再分发边界。
- npm/node 安装期间可能出现 transitive `ini` engine warning；本机 Node `24.8.0` 下安装和运行通过，该 warning 不构成产品失败。
- 不创建第二宿主、Web UI、自定义 TUI 或模型权重训练/捆绑；不恢复旧 Claude/Codex、Pi 或 Superpowers runtime。

## 延后事项

- 安装器的独立收敛与更多发布渠道。
- Solver 并发、跨 Case 监督反馈、显式 reopen/migration 和第二个 Agent 宿主。
- 完整 benchmark 评估、自动参数调节、自定义 LLM runtime。
- 捆绑 TeX 发行版或 embedding 权重。
