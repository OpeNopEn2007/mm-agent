# v1.0.0 Roadmap

## 目标

构建第一个可用的 OpenCode Plugin 版 MM-Agent Harness，把 Canonical Core 落地为端到端 Case。

当前状态：Step 1–8 已接受；`v1.0.0` 保持未公开发布的本机 RC。本轮不 commit、tag、push 或 npm publish，用户体验后的反馈将决定 RC2 或正式发布。

`v1.0.0` 的 Canonical Core 在 `4ce82cd` 接受，OpenCode Adapter 设计在 `1040e63` 接受：

- [Canonical Core](../architecture/canonical-core.md) 定义宿主无关的 Case、artifact、context manifest、review 和 gate 协议。
- [Artifact 协议](../context/artifact-protocol.md) 定义 Case 文件职责、状态推进和完成规则。
- [OpenCode Plugin Harness](../architecture/opencode-plugin-harness.md) 是 v1 唯一 Adapter。

Pi CLI Extension 与旧 Claude/Codex Plugin 不再是活跃 runtime 决策，资产保留在 `.archived/legacy-claude-codex-plugin/`，仅供回溯。

## 验收标准

- 一个赛题文件可以启动一次 Case 运行。
- 用户通过唯一入口 `/mm-agent` 创建或恢复 Case。
- 论文四阶段按顺序执行。
- 阶段 artifacts 写入 `runs/<case-id>/`，路径全部 Case 内相对。
- 每个 subagent 从 `context.json` 和 accepted artifacts 重建 fresh context，不依赖前序聊天。
- `state.json` 只能通过 `mm_agent_case gate` 推进；`gate` 使用调用方 `expected_revision` 做 compare-and-swap，并校验 Manifest 的 read-set hash 与 promotion target 白名单。
- Case Policy 与四个 Rubric 快照在 `open` 时固化到 `case.json.policy`；Solving Stage 按 `solving_per_task` 为每个 Task 建立独立 revision budget。
- 每阶段有 fresh Critic 审查；Critic 复用同一 Attempt Manifest，不创建第二个 Attempt。
- Blocker 以追加式记录存在 `state.json`，由同 scope Actor Attempt 通过 `resolves_blocker` 解决。
- Runtime Evidence（检索、计算、编译）作为合法 required read source。
- HMML 检索可供建模阶段使用，检索结果记录模式、模型、revision、index hash 和分数。
- 计算求解阶段产出代码/结果与 Runtime Evidence，或产出有理由的直接洞察 artifact。
- 报告生成阶段产出 `main.tex`、`compile.log` 和非空 `report.pdf`，并由 Report Gate 验证。
- 完成证据由 `inspect` 实时从文件推导，不写入第二份状态。
- OpenCode 重启后可从本地 Case 状态恢复；正确性不依赖 compaction hook。
- 外部解包 RC 可以通过项目级 `.opencode/plugins/` 与 `.opencode/skills/` 发现，无需修改全局配置。
- MIT License、第三方 notices、README、package 清单和实际运行面一致。
- external RC 完整通过 minimal、multi-wave 与 MM-Bench `2024_C`，每个 completed Case 的 fresh recovery 不重派。
