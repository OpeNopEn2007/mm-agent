# 设计原则

## Harness 高于 Prompt

`mm-agent` 不应该只是一个聪明的 prompt 包。它应该是一个本地 Harness，负责协调工具、artifact、反馈和报告生成。

## 忠于论文，务实工程

MM-Agent 论文定义工作流形状。工程实现负责判断：为了让这个工作流在本地跑起来，最小需要哪些机制。

## Artifact 是接口

智能体之间应该通过持久 artifact 传递上下文，而不是依赖隐藏对话状态。如果某个信息对下一阶段重要，它就必须被写下来。

## Case 是学习单位

每个赛题运行都是一个 Case。一个 Case 包含输入、中间 artifacts、最终报告、日志和反馈。后续改进应该来自 Case 与 Case 之间的比较。

## 报告是产品

最终 PDF 才是产品。中间 artifacts 重要，是因为它们解释、修复并改进最终报告。

## 最小表面积

优先选择更少的命令、更少的文档分类、更清晰的契约。只有当抽象能真正消除复杂度时，才增加抽象。
